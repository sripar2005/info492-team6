Can an agent pull a contract's rules into a form we can check?

Before an agent can check a change proposal at each handoff, the contract's pricing and notice rules have to exist as structured, citable data. This demo asks Claude to extract them from a GC/CM contract and scores the result against a hand-built answer key.

How it works and what it can't show

D-401.5

Method

  1. Split the contract at each Article and Exhibit: 19 sections in 6 API calls.
  2. Extract with Claude through a structured tool schema: type, sections, value and unit, trigger, exceptions, and an exact quote.
  3. Verify every quote against the contract text.
  4. Score: a key rule is found when an extracted quote overlaps its anchor and the number and unit match.

The answer key was never shown to the extractor. Prompts, key, and target were fixed before the run.

Limits

  • The contract is synthetic, modeled on the Webster School GC/CM project. Dollar breakdowns, rates, deadlines, and party names are invented.
  • One contract is one case.
  • The key and contract share an author, so a match partly tests reading clear text.
  • Matching by text overlap can miss a correct rule that quotes a different part of the clause.
  • The answer key is a draft awaiting teammate review.
