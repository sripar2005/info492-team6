Four parties, four agents, one contract.

Every priced change proposal passes through the subcontractor's, GC/CM's, Architect's, and Owner's PM's agents. Each checks it from its own seat, within its own authority, quotes the clause, and hands a message to the next party. People make every decision. We scored the agents on 36 change proposals with 33 seeded contract issues, and compared them with a rules-and-keywords checker that uses no AI.

How it works

Each agent gets the contract, the rule card Demo 1 extracted from it, the change proposal as its party sees it, and a calculator sheet computed by code. Agents judge; code does arithmetic and dates.

1 · agentSubcontractor

Sees only its own quote. Checks markup limits, breakdown, T&M tags.

2 · agentGC/CM

Checks sub pricing, backup, tie-out before the CP goes out.

3 · agentArchitect

Checks the work is really a change from the drawings and specs. Can't approve cost.

4 · agentOwner's PM

Follows an owner-side PM's review order. Recommends, returns, or escalates.

5 · personDecision

A person approves, returns, or takes a claim to the Board.

  • Message envelope: every handoff records from, to, authority, decision, flags with section and quote, and a message to the next party.
  • Audit trail: envelopes are appended in order with IDs, model, and time; people's decisions are added on top.
  • Escalation: delay claims, site conditions, and amounts over the $250,000 limit always go to a person.
  • Integration: Demo 1's extracted rules feed every agent; Demo 2's deadline code computes notice dates.
  • Data: 36 change proposals on Demo 1's synthetic GC/CM contract, including 6 where the sub's quote arrives as email text. See the data note.
  • Model: an open model running locally through Ollama, so no project data leaves the machine and there's no API cost. The same code also runs on Claude through the API.

Stakeholder testing

Who tested Demo 3 and what changed because of it.

From the interview (owner-side PM, 30+ years)
  • “AI is great at the math.” → arithmetic moved to code; agents only judge.
  • Follow the PM's review order → the Owner's agent checks cover sheet, backup, markups, covered costs, equipment, notice, then claims.
  • Delays and site conditions are the hard part → those always escalate to a person instead of getting scored.
  • Sub markups over the limit → seeded in 6 cases, owned by the GC/CM agent.

Limits

  • The change proposals, labels, prompts, and baseline keyword lists were written by the same team, so the test favors whatever we expected. A second, independent set is the next step.
  • 36 proposals on one synthetic contract; real packages are longer PDFs with drawings and email threads.
  • One run per model; model outputs can vary between runs. Four Llama proposals (CP-0209 to 0212) were rerun after one machine crashed on a malformed reply; we changed only the error handling, not prompts or labels. One owner review (CP-0210) still failed and counts as no flags.
  • Human actions in the dashboard are stored in your browser only, for the demo.
